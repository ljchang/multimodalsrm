## MultimodalSRM

`from multimodalsrm import MultimodalSRM` · [Source](https://github.com/ljchang/multimodalsrm/blob/main/src/multimodalsrm/estimator.py#L82)

```python

    *,
    latent_dt,
    responses=None,
    latent_pooling="shared",
    latent_strength=1.0,
    modality_weights=None,

    loading_penalty_scaling="pair",
    latent_ridge=None,
    latent_timescale=None,
    temporal_strength=None,
    max_iter=100,
    tol=1e-05,
    n_init=1,

    init="random",
    random_state=None,
    gap_threshold=None,
    kernel_max_iter=50,
    balance_scale=True,
    kernel_tol=0.0001,
    kernel_extrapolation=True,
    lag_init=None,
    edge_observations="include",
    response_penalty_scaling="objective",
)
```

Regularized multimodal factor model; arrays are time by feature.

By default, one latent response per run is shared exactly across participants
and modalities, with separate participant–modality maps and response kernels.
`affinity_` represents this sharing as a complete graph with unit edges;
exact equality is enforced independently of `latent_strength`.

`latent_timescale` (default 2.0, in timestamp units, normally seconds)
sets how smooth the latent response is assumed to be. The latent penalty is
`latent_ridge * (mean z**2 + latent_timescale**2 * mean (dz/dt)**2)`: a
fluctuation with period `2 * pi * latent_timescale` costs twice as much
as a constant of the same amplitude, and faster fluctuations cost more.
Increase it for a smoother latent, decrease it to follow faster changes;
zero removes the link between neighbouring latent nodes, which leaves
nodes without an observation unconstrained. It is a prior correlation time,
like the GP model's `length_scale`, not a hard cutoff: strong, clean data
can still express faster structure. `latent_ridge` (default 0.1) sets the
weight of that whole penalty. Rescale `latent_timescale` with the data's
time unit. Both are tuning choices; compare values by held-out prediction.

`temporal_strength` is the deprecated previous parameterization,
`latent_ridge * mean z**2 + temporal_strength * mean (dz/dt)**2`. Passing
it reproduces earlier fits, including the earlier `latent_ridge` default
of 1e-4, and cannot be combined with `latent_timescale`.

`lag_init="scan"` estimates relative modality delays from the training
observations before fitting (see `scan_lags`), starts every free response
lag there and narrows its bounds to that lag plus or minus two timestamp
units. Without it, lags start at the configured kernels and a true relative
delay outside the bounds, or far from the start, can end in a wrong optimum
with no bound flagged. A precomputed `LagScan` is also accepted. The scan
is stored as `lag_scan_`. When it is unreliable the responses are left as
configured and a warning says so: weakly coupled modalities often give no
usable scan, and then the configured lags and bounds are the better start.
Only relative timing is identified: `timing_report()` states fitted peak
delays relative to a reference modality, by default the first.

A response reads the latent over its whole support envelope, which covers
every lag its bounds allow and the response's full tail. With
`edge_observations="include"` (default) each latent grid is extended
before and after its run by the envelope's reach, so every observed row is
scored, and the extension is then dropped: reported latents cover the run
only. This is the "same" mode of a convolution. The added latent is
constrained only by the edge observations and the smoothness penalty, so
predictions near a run's start rest on less information than interior
ones. `"exclude"` is the "valid" mode: an observation is scored only if
its envelope lies inside the run, so long responses, wide lag bounds and
short runs can discard much of a recording.

`response_penalty_scaling` sets how `Response.lag_prior`, `Response.prior` and
`pooling_strength` weigh against the data. The reconstruction loss is a
normalized mean, not a sum over observations. With `"objective"`
(default, the original behaviour) those penalties are added to it unscaled,
which makes them far stronger than their stated values suggest: a
`Normal(0, 1)` lag prior can act like a standard deviation of a few
hundredths of a second, and `pooling_strength=1` like complete pooling.
`"likelihood"` multiplies each by the factor that a Gaussian likelihood
over the scored observations would imply, assuming unit residual variance
in standardized units, so a lag prior's `sd` is in seconds and
`pooling_strength` is `1 / sd**2` of the spread between participants,
summed over participants. Residual variance below one makes these priors
somewhat tighter than stated. Factors are stored in `penalty_scale_`.

Penalties and balancing conventions are recorded in `configuration_`.
Reaching `max_iter` does not constitute convergence. `init="hybrid"`
uses one deterministic spectral start followed by paired random starts;
`init="spectral"` repeats the same start redundantly at every restart.

`n_jobs` runs independent restarts in isolated processes (default 1;
-1 uses available CPUs, capped by `n_init`). Integer `random_state`
preserves restart seeds and selection across worker counts. Native parallel
cross-validation suppresses inner restart workers to avoid oversubscription.

Convergence requires a small objective decrement, a successful response
optimizer and, with `kernel_tol` (default 1e-4), that no free response
coordinate moved further than it in the last iteration: seconds for lags,
log units for positive parameters. Alternating updates can move a response
by a small, nearly constant step for hundreds of iterations while each
objective decrement stays below `tol`; `kernel_tol=None` restores the
objective-only rule. `kernel_extrapolation` (default True) follows each
iteration's response step further while refitted latents and maps keep
lowering the complete objective, which shortens that slow phase without
changing the objective or its stationary points.

### MultimodalSRM.timing_report

```python
MultimodalSRM.timing_report(reference=None)
```

Fitted response timing relative to a reference modality.

Reports each modality's peak delay, pairwise differences, the clock
origin that was subtracted, lags resting at a bound, and agreement
with the lag scan when one was used. `reference` names the modality
shown at zero. It only changes how delays are displayed: the fit and
the pairwise differences are the same for every choice. By default it
is the first modality whose lag is not estimated, or the first
modality in `responses` when every lag is estimated.

## BayesianMultimodalSRM

`from multimodalsrm.bayesian import BayesianMultimodalSRM` · [Source](https://github.com/ljchang/multimodalsrm/blob/main/src/multimodalsrm/bayesian/model.py#L34)

```python
BayesianMultimodalSRM(
    *,
    priors,
    anchor=None,
    features=1,
    factor_anchors=None,
    reference_modality=None,
    responses=None,
    length_scale=3.0,
    inference="posterior",
    search=None,
    sampler=None,
    sample_blocks=None,
    random_state=0,
    max_observations=800,
    covariance_tolerance=1e-07,
    linear_algebra="dense",
    spectral=None,
    run_baseline_sd=None,
    noise_timescales=None,
    response_quadrature_order=None,
    state_space_gaussian="auto",
    edge_observations="auto",
)
```

Experimental Bayesian SRM with a shared GP timescale.

`features>1` supports MAP with dense/grouped/state_space algebra. Optional
`factor_anchors` select a training QR reporting rotation; without them,
the fitted optimizer coordinates are retained. Explicit anchors must name
one observed training feature per factor, starting with `anchor` when
supplied. Raw optimizer parameters remain unchanged. For MAP coordinates,
use loadings `W_raw @ configuration_['factor_orientation']['rotation']`.
All factors share modality filters and GP timescale. Multifactor posterior
supports dense/grouped Identity/Gaussian responses, plus Gamma/DoubleGamma/BatemanSCR
with explicit response quadrature, with white noise and
explicit training anchors. `reported_parameter_draws()` applies a separate
positive-diagonal QR to each draw; raw draws and diagnostics are unchanged.
Latent mixtures use the same draw-specific coordinates and full conditional
covariance in each projection. These are reporting conventions only.
Multifactor spectral mode and run baselines remain unsupported. Full
dense/grouped posterior supports explicit joint donor/participant updates.
`sample_latent` returns joint conditional trajectory draws.

`priors` describes loadings, offsets, noise variance and free response
parameters. A numeric `length_scale` fixes the latent GP correlation
timescale in timestamp units. Pass a `Prior` with positive finite bounds
to learn one shared timescale, keeping latent variance fixed at one. This
supports dense/grouped MAP and posterior with Identity/Gaussian responses
or quadrature Gamma/DoubleGamma/BatemanSCR, independent noise and no run
baselines. It is not a response width.
Optional `anchor=(subject, modality, feature)` sets a positive loading
for one factor; otherwise the first sorted eligible training feature is
used. The anchor may have any supported response family.
Optional `reference_modality` names a modality with a fixed lag (shape
may be learned) to report other lags against. It is a reporting
convention: it does not change the likelihood, and `timing_report` can
use any modality as its reference after fitting. Without it an already
fixed lag is used if available; with all lags free, proper supplied priors
define the common offset and lag summaries show the first modality at
zero. Latent queries and lag priors/bounds
remain in model-clock coordinates. No convention establishes physiological
timing or identifies disconnected data components.
The model consumes supplied units without standardization. MAP and NUTS
share a proper physical parameter density and marginalize the latent GP.
Sampling diagnostics do not establish calibration or complete mode coverage.

`linear_algebra="grouped"` opts into an exact reduction over repeated
modality/time functionals. `"dense"` remains the default reference.
The capacity guard counts scalars for dense algebra and nodes times factors
for grouped algebra.

`linear_algebra="state_space"` uses exact Matérn-3/2 Kalman inference
with stationary initialization and native observation times. It groups
filtering and smoothing updates at exact modality/time nodes for fixed or
learned responses when the noise prior has strictly positive support.
Noise priors admitting zero retain scalar updates.
MAP supports Identity, Gaussian, or integer-shape Gamma/DoubleGamma responses
and independent observation noise. Widths/scales, undershoot ratios, and
lags may be learned; Gamma shapes remain fixed. Gaussian responses use
a qualified rational approximation; Gamma tails are restored. A temporal
covariance error bound is checked over the full declared parameter domain
against covariance_tolerance. `state_space_gaussian="auto"` tries compact
rational banks before the larger Laguerre representation; either method
can be requested explicitly. BatemanSCR learns rise, decay and lag with two
response states and an explicit bound for the restored 90-second tail.
SampledKernel remains unsupported.
Prediction uses an RTS smoother; no dense observation covariance is built.
max_observations then bounds modality/time nodes per run and can be raised.

`linear_algebra="spectral", spectral=SpectralConfig(rank, padding)`
explicitly approximates the GP with a padded sine basis. Its finite rank
and boundary errors require separate numerical and posterior validation.
Boundaries can introduce spurious common-lag likelihood dependence; this
does not establish absolute physiological timing.
Gaussian coefficients are marginalized exactly within that approximation.

`response_quadrature_order` explicitly enables finite response-functional
quadrature for Gamma, DoubleGamma, BatemanSCR (and Gaussian/Identity).
Orders 8..1024 are per integration panel. This path supports dense/grouped
MAP and posterior sampling, including continuous shape estimation. The latent process
remains continuous; response integrals and L2
norms are approximate. `covariance_tolerance` does not certify this path:
compare higher orders and independent integrals for the declared bounds.
Approximation metadata is retained in configuration, queries and archives.

`edge_observations="include"` scores every observation in a run, and
queries are valid anywhere inside it. The latent GP is stationary and
defined outside the run, so nothing is added to the model. `"exclude"`
uses an observation only if its response's support envelope, which covers
every lag the bounds allow and the response's full tail, lies inside the
run; long responses and wide lag bounds can then discard much of a short
recording. The default `"auto"` includes for dense, grouped and
state-space algebra, which agree with one another on edge observations,
and excludes for spectral algebra: its basis lives on the padded run, so a
response reaching beyond the padding would read an extrapolated latent.
The resolved choice is `edge_observations_` after fitting.

`run_baseline_sd={modality: sd}` optionally adds independent zero-mean
Gaussian offsets per participant/run/feature, in supplied observation units.
Their fixed prior SDs are explicit; offsets are analytically marginalized.
Dense/grouped calculations support them; spectral does not yet. Prediction
includes baseline uncertainty even with `include_noise=False`; the shared
latent excludes these offsets. None/zero preserves the original model.

### BayesianMultimodalSRM.condition

```python
BayesianMultimodalSRM.condition(
    donors,
    *,
    targets,
    donor_layout="runs",
    mode="joint",
    progress=None,
)
```

Condition independent new runs after removing target payloads.

`mode="joint"` (default) refits training plus current donors.
`mode="frozen"` uses the original training MAP without optimization
or sampling and conditions each new run's common GP on current donors.
Frozen mode requires a MAP fit; uncertainty excludes parameter
uncertainty. Returns an independent estimator. Chained calls retain
the training/calibration reference and replace the current donor batch.
Target payloads are removed before validation and support selection.

### BayesianMultimodalSRM.relative_lag_draws

```python
BayesianMultimodalSRM.relative_lag_draws()
```

Relative modality lags, in timestamp units (normally seconds).

Return read-only arrays with the original (chain, draw) axes, including
fixed modalities. MAP gives shape (1, 1). A fixed reference lag is
subtracted when available. Without one, subtract the first modality's
lag separately for each draw, as `timing_report` does by default,
preserving all pairwise differences. This shifts summaries only: latent query times
and lag priors remain in model coordinates. It does not establish
absolute timing identification or calibrated uncertainty.

### BayesianMultimodalSRM.timing_report

```python
BayesianMultimodalSRM.timing_report(reference=None, *, max_draws=200, uncertainty=None)
```

Peak response delays relative to a reference modality.

The same convention as `MultimodalSRM.timing_report`. Each retained
parameter draw gives one peak delay per modality, so posterior fits
report a mean, standard deviation and the draws; MAP gives one value.
For Gamma, DoubleGamma and BatemanSCR the peak is far better
determined than the `lag` parameter that `relative_lag_draws`
reports, which is their onset. `reference` names the modality shown
at zero and only changes how delays are displayed. By default it is
the modality `relative_lag_draws` uses: `reference_modality` when
that was set, otherwise a modality whose lag is not estimated,
otherwise the first modality in `responses`. `max_draws=None` uses every draw. This does not
establish physiological timing.

`uncertainty="laplace"` adds `report["lag_standard_error"]` for a
MAP fit with dense, grouped or state-space algebra: standard errors of
each lag, each lag relative to the reference, and each pairwise lag
difference, from the inverse Hessian of the negative log posterior at
the MAP. They are model-based: they assume the model is correct and
are too narrow when it is not. They refer to the `lag` parameter,
which is the peak delay for Identity and Gaussian responses and for
any response whose only free parameter is its lag
(`applies_to_peak_delay`); widths and other shape parameters get no
standard error. A lag resting on a bound gives NaN and is listed in
`lags_at_bounds`; `positive_definite=False` means the fit is not
at a local optimum and the errors should not be used; and the block
records how many zero Hessian directions were found and expected. The cost is
one Hessian-vector product per parameter plus a dense
eigendecomposition, and more than 2000 parameters raise an error.
Posterior fits raise too: their draws already give a standard
deviation.

### BayesianMultimodalSRM.transform

```python
BayesianMultimodalSRM.transform(
    data,
    *,
    times,
    modalities=None,
    data_layout="runs",
    readout="gp",
)
```

Infer each participant's held-out latent using only their observations.

Returns `{subject: {run: GaussianMixtureSeries}}` in the original
training MAP coordinates. Parameters are fixed, including filters and
preprocessing; no optimization or sampling occurs. Known participants
and new run IDs are required. `times` is an explicit query vector or
run-to-vector mapping. Observations retain their native clocks/masks.

`modalities` optionally selects a nonempty list before reading any
excluded payload. Every supplied participant/run must retain input.
Uncertainty is conditional on the training MAP. Independent estimates
concern the same model latent; they do not introduce private factors.

`readout="gp"` uses the fitted temporal prior. `"instantaneous"`
uses its unit-variance marginal prior and same-timestamp observations
only: selected modalities must have Identity responses, white residual
noise and no run baselines; spectral fits are unsupported. Only exact
observed timestamps with at least one available feature are valid.
Its uncertainty belongs to this instantaneous marginal model, not the
full GP posterior. Neither readout refits or changes the trained model.

### BayesianMultimodalSRM.sample_latent

```python
BayesianMultimodalSRM.sample_latent(
    *,
    times,
    max_draws=200,
    draws_per_parameter=1,
    random_state=None,
    max_joint_size=2048,
)
```

Draw joint shared latent paths from an existing parameter posterior.

Returns one `TrajectorySamples` per run, with sample axes parameter
draw / conditional draw / time / factor. All times and factors in a
path are sampled jointly in that parameter draw's fitted reporting
coordinates. No MAP search, MCMC or preprocessing is performed.

Supports dense/grouped Identity/Gaussian and quadrature Gamma/DoubleGamma/BatemanSCR
posteriors with independent observation noise. `max_draws` balances retained draws
across chains, as in `infer_latent`. `random_state` seeds NumPy's
local generator; the model's sampling seed and state are unchanged.
Increasing `draws_per_parameter` does not increase parameter ESS.

`max_joint_size` bounds query times times factors per run, since
joint covariance storage and factorization scale quadratically and
cubically in that size. Invalid times remain NaN, as in marginal
queries. Separate calls/windows do not preserve cross-call correlation.

### BayesianMultimodalSRM.condition_participants

```python
BayesianMultimodalSRM.condition_participants(
    data,
    *,
    sampler=None,
    random_state=None,

```

Fit independent participant updates on distinct new stimulus run IDs.

Return a participant-to-posterior mapping. Each target combines the saved
